# Zoomies GP — iOS (Capacitor)

The native shell around the same `dist/` bundle the web deploy and the
Electron/Steam build use. Generated by `npx cap add ios`, then committed —
the project carries real state (signing team, store settings), so it is
source, not build output. `ios/.gitignore` keeps Pods/build/DerivedData and
the synced web bundle (`App/App/public`) out of git.

## Build & run

```sh
npm run cap:sync   # build dist/ + copy it into the iOS project
npm run ios        # open the Xcode workspace
```

Then run on a device from Xcode as usual. Repeat `cap:sync` whenever the
web app changes; nothing in Xcode needs touching for a content update.

## App Store notes

- **Identity**: bundle id `app.thea.zoomies`, display name "Zoomies GP",
  version comes from MARKETING_VERSION in the project.
- **Orientation**: landscape-only, with `UIRequiresFullScreen` set — an
  iPad build that locks orientation MUST opt out of multitasking or App
  Store validation rejects it.
- **Export compliance**: `ITSAppUsesNonExemptEncryption=false` is set
  (HTTPS only), so uploads skip the encryption questionnaire.
- **Privacy**: `App/App/PrivacyInfo.xcprivacy` declares no tracking and no
  data collection (saves are on-device; multiplayer is room-code based with
  no accounts). ONE-TIME STEP: drag it into the App target in Xcode (tick
  "App" under target membership) so it ships in the bundle — files added
  outside Xcode aren't in the build phase until then. The App Store Connect
  privacy questionnaire answers should match: no data collected.
- **Motion permission**: tilt steering uses the web DeviceMotion API, which
  prompts inside WKWebView on first use — no Info.plist usage string is
  required for the web API (that key is for the native CoreMotion path).

## Archive / upload

Xcode → Product → Archive → Distribute App → App Store Connect. The first
upload needs the app record created in App Store Connect with the same
bundle id.
